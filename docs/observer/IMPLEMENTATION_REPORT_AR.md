## النتيجة وحدود التنفيذ

أضيف دور مستقل `observer` باسم «المراقب». تعرض له مسارات صفحات البرنامج الفعالة بياناتها للقراءة عبر صفحة مراقبة تستخدم مكونات البرنامج الحالية: الجداول والبطاقات والأزرار والبحث والترقيم. لا يحصل على دور المالك أو الأدمن، ولا يُغيّر الدور المصادق عليه في سياق الطلب.

**هذا عرض مستقل للسجلات في المسارات الحالية، وليس نسخة من كل واجهة تشغيل أصلية بعد تعطيل أزرارها.** تعرض صفحات التقارير السجلات المرتبطة بها؛ لا تعيد بناء رسومها أو حسابات تقاريرها الأصلية. تعرض صفحة النسخ الاحتياطية بيانات النسخ دون رابط تنزيل النسخة الكاملة. وتبقى صفحات الذكاء والترجمة والإنشاء والصرف والاستلام للقراءة فقط. بعض العلاقات تظهر بمعرفاتها، وبعض عناوين الحقول تستخدم اسم الحقل عند غياب تسمية عربية.

التفعيل على بيئة المستخدم ينتظر التحقق اليدوي من عمود `users.role` وإضافة قيمة `observer` عند الحاجة، ثم إنشاء حساب أو إسناد الدور من إدارة المستخدمين. لم يتصل الوكيل بقاعدة البيانات ولم يشغّل التطبيق أو ينفّذ SQL، ولم يقرأ أو يعدّل المجلد Copy (2).

## المقارنة قبل وبعد

| الجزء | قبل | بعد |
|---|---|---|
| الأدوار | لا يوجد مراقب | دور مستقل مترجم في قائمة إدارة المستخدمين |
| حماية السيرفر | حارس مركزي للمشتريات وحراس داخل أقسام أخرى | حارس إضافي في قاعدة جميع إجراءات tRPC يمنع المراقب افتراضيًا؛ حراس الأدوار السابقة باقية |
| قراءة المراقب | غير متاحة | مسار قراءة محدد بقائمة صفحات ومصادر وحقول ثابتة، دون اختيار جدول أو دور من العميل |
| كتابة اسم صفحة مباشرة | تخضع للصلاحيات الأصلية | الصفحة المعروفة تعرض القراءة؛ المسار غير المسجل لا يفتح خدمة تشغيل |
| محاولات التغيير عبر API | الصلاحيات الأصلية لكل دور | رفض للمراقب قبل تنفيذ الإجراء، ولو غُيّر الجسم أو الرأس أو أُرسل طلب مجمع |
| الأدوار الأخرى | الواجهات والإجراءات الحالية | نفس واجهاتها وحراسها وعائلات أدوارها؛ اجتازت اختبارات المقارنة |

## آلية المنع

- الحارس يستخدم الحساب الذي تحققت منه جلسة السيرفر، ونوع الإجراء الحقيقي ومساره، وليس دورًا أو نوع طلب يرسله العميل.
- القائمة المسموحة للمراقب: استعلام `auth.me` واستعلام `observer.readPage`، و`auth.logout` لتنظيف جلسة الدخول. بقية الاستعلامات والتعديلات والاشتراكات مرفوضة افتراضيًا.
- يلزم حساب مراقب نشط لخدمة القراءة. لا يستطيع المالك أو الأدمن استخدام هذه الخدمة بوصفه مراقبًا؛ تبقى خدماتهم المعتادة لهم.
- مسار القراءة ينفّذ `SELECT` فقط، مع معاملات للقيم، و25 سجلًا في الصفحة، وحدود للبحث والصفحات. لا تُستمد أسماء الجداول أو الأعمدة من إدخال المستخدم. صفحات التفاصيل ترشح السجل والبيانات التابعة برقم المستند.
- الرفع ومسارات REST المحمية بالمصادقة ترفض المراقب، ومسارات التصدير تبقي قوائم أدوارها السابقة التي لا تشمل المراقب.
- حُجبت حقول كلمات المرور والمفاتيح ورموز المصادقة ومسارات ملفات النسخ، مع تنقية مفاتيح المحتوى المتداخل. هذه تنقية حقول وJSON وليست ضمانًا لاكتشاف كل سر قد يُكتب داخل نص حر.
- أوقفت للمراقب استدعاءات إشعارات الواجهة وتسجيل اشتراك Push وتدقيق قرار تحديث PWA. لم تتغير إجراءات الدخول العامة الأصلية أو تدقيق الدخول أو خدمات الخلفية؛ لا يعني منع الكتابة التشغيلية إيقاف دورة المصادقة أو وظائف السيرفر العامة.
- أي صفحة جديدة مستقبلًا تحتاج تسجيلًا صريحًا في قائمة صفحات المراقب. لا تُمنح تلقائيًا.

## الاختبارات

نجحت **381 حالة معزولة**، دون تحميل إعدادات اتصال أو تشغيل سيرفر التطبيق:

- 15 اختبار Node للدور الجديد: المسارات والمصادر، الصلاحية الحقيقية، الحساب غير النشط، رفض التعديلات، HTTP داخل الذاكرة والطلبات المجمعة، مدخلات القراءة، SQL بمعاملات، إخفاء حقول الاعتماد، ومطابقة أعمدة الفرق مع عقود الجداول الحالية.
- 9 اختبارات واجهة للمراقب: القراءة والبحث والترقيم والروابط المباشرة وعدم عرض نماذج التشغيل، النص غير الموثوق، وبقاء راوتر وقائمة الأدوار السابقة.
- 74 اختبارًا لحارس الصلاحيات المركزي السابق.
- 226 اختبار Node لمسارات فرق التذاكر والمخزون والشراء والتكاليف والتحسين الحالية.
- 57 اختبار واجهة لمسارات مواد التذاكر وPMV2 والإضافة التخزينية والبطاقات الحالية.

تحويل صيغة ملفات التشغيل العشرين نجح دون استيراد التطبيق. مقارنة TypeScript للمصدر قبل وبعد: **663 تشخيصًا في الحالتين، دون تشخيص جديد أو محذوف**. الفحص العام للمشروع ليس ناجحًا بسبب أخطائه السابقة. لم يجر اختبار قاعدة أو متصفح حي.

## أوامر القاعدة — ينفذها المستخدم يدويًا

لا جدول جديد ولا إعادة توزيع صلاحيات أو تحديث حسابات موجودة مطلوب. التغيير المحتمل هو إضافة قيمة `observer` في نهاية ENUM الحالي لعمود الدور فقط.

1. نفذ `sql/01-inspect-role.sql`: يعرض التعريف الفعلي لعمود الدور.
2. نفذ `sql/02-prepare-role-command.sql`: هذا **SELECT للقراءة فقط**، يعرض التعريف الحالي وعمود `next_command`. إذا ظهر أمر `ALTER TABLE` انسخه ونفّذه يدويًا. يولّد الأمر من تعريف قاعدتك ليحافظ على الأدوار الحالية وترتيبها والإعدادات الافتراضية وNULL والترميز والتعليق. إذا ظهرت رسالة عدم الحاجة فلا تنفذ ALTER، وإذا ظهر تعريف غير مدعوم أرسل النتيجة لمراجعته.
3. نفذ `sql/03-verify-role.sql`: يتحقق من التعريف ويعرض أعداد الحسابات لكل دور؛ أرسل النتيجة. لا تعدّل حسابك الإداري الأساسي؛ أنشئ حسابًا مستقلًا للمراقب أو اسند الدور لحساب اختبار من صفحة المستخدمين بعد التحقق.

لم يُنفَّذ أي من هذه الأوامر بواسطة الوكيل. لا تشغّل ترحيل Drizzle أو push شامل للمخطط لتفعيل هذه الإضافة.

## الاختبار العملي بعد التفعيل اليدوي

1. بحساب أدمن: أنشئ حساب مراقب مستقل، ثم افتح جلسة منفصلة له.
2. افتح التذاكر والمشتريات والمخزون وPMV2 والإنشاءات والمستخدمين والتدقيق. تحقق من قراءة السجلات والبحث والتنقل.
3. اكتب مباشرة `/tickets/new` أو رابط تحرير مشروع؛ يجب أن يظهر عرض القراءة فقط، بلا نموذج حفظ أو إرسال. رابط غير مسجل يجب ألا يفتح خدمة تنفيذ.
4. جرّب من أدوات المتصفح استدعاء تعديل قديم بحساب المراقب: النتيجة المتوقعة `FORBIDDEN` دون تغيير السجل. لا تجرب إجراءات فعلية من حساب المالك أو الأدمن لهذا الاختبار.
5. تحقق من غياب كلمات المرور ورموز الاعتماد وروابط النسخ الكاملة، ومن نجاح تسجيل الخروج.
6. ارجع لحساب الأدمن وفني ومستودع؛ اختبر إجراء معتاد لكل منها. صلاحياتها وعرضها الأصليان يجب أن يبقيا كما كانا.
