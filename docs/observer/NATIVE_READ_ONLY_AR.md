## كيف يعمل التصحيح

- الجلسة والحساب والقاعدة وذاكرة `auth.me` تحتفظ بالدور الفعلي `observer`. لا يتم تغيير حساب إلى أدمن أو استعارة رقم مستخدم إداري.
- `useAuth` يقدّم نطاق عرض الأدمن للمكونات الأصلية، مع حقلي `authenticatedUser` و`isReadOnly` لمعرفة الدور الفعلي. يظهر اسم الدور الحقيقي «المراقب» في القائمة، وشارة «استعراض فقط» في المحتوى.
- الحارس العام عند السيرفر يتحقق أولًا من الهوية المصادق عليها والحساب النشط ونوع الإجراء ومساره. يمنع كل تعديل أو إجراء غير مسجل للمراقب قبل الوصول إلى حراس القسم أو التنفيذ.
- بعد اجتياز الحارس فقط، يحصل الاستعلام الأصلي المسموح على نطاق قراءة الأدمن. يحتفظ السياق بهوية المصادقة الأصلية، ويعيد الحارس استخدامها إذا استدعى الكود راوترًا داخليًا؛ فلا تتحول صلاحية العرض إلى صلاحية كتابة.
- القائمة الصريحة تضم 286 استعلامًا أصليًا. المسارات الجديدة أو غير المسجلة مرفوضة افتراضيًا. `warehouseReceipts.getForPrint` مرفوض لأنه مخصص للطباعة. استثناءا نوع mutation هما `auth.logout` لتنظيف الجلسة، و`nfc.scanTag` الذي يبحث ويعرض أصلًا دون إجراء كتابة؛ لا تمنح هذه الاستثناءات حق تعديل.
- حماية إضافية حول عميل SQL تعمل داخل سياق قراءة المراقب فقط. تسمح باستعلامات القراءة وضوابط المعاملة اللازمة للقراءات المتسقة، وتمنع DML/DDL والقراءات المقفلة والتصدير إلى ملف قبل وصول الأمر إلى الدرايفر. سياقات المستخدمين الآخرين ووظائف الخلفية لا تحصل على هذا القيد.
- أُبقيت صلاحيات PMV2 والفرق القديمة كما هي. الاستعراض الموسع للحساب الفعلي `observer` يعمل فقط داخل سياق القراءة المحدد، دون إضافة عضوية فريق أو إدراجه في عائلات المنفذين.
- سلوكا الكتابة اللذان يظهران أثناء قراءة بيانات موجودة — تجهيز ترجمة سجل، وإغلاق دفعات تسعير فارغة — يتم تجاوزهما للمراقب فقط. يظل سلوكهما الأصلي للأدوار الأخرى.
- حماية الواجهة تعمل للمراقب فقط، وتغطي الأزرار والقوائم المنبثقة بالـportals والنماذج وروابط التنزيل ورفع الملفات. تبقى التبويبات والبحث والفلاتر والتحديث والتنقل وعرض التفاصيل متاحة. نماذج الإنشاء والتحرير بالروابط المباشرة تعرض محتواها الأصلي داخل حقول معطلة.
- الرابط الوسيط للـAPI في العميل يوقف إجراءات المراقب الممنوعة قبل النقل. حارس السيرفر مستقل عنه ويمنع التجاوز عند حذف قيود الواجهة أو تزوير الطلب.
- حقول كلمات المرور والمفاتيح ورموز المصادقة محجوبة. يحتفظ JSON النصي بنوعه لتعمل شاشة التدقيق الأصلية. رمز تتبع اللوت التجاري يبقى للعرض؛ روابط النسخ الاحتياطية الكاملة محجوبة. لا يُعدّل المحتوى المخزن.
- اختيار اللغة للمراقب يبقى محليًا في الواجهة، دون كتابة تفضيل حسابه في القاعدة. لا يسجل اشتراك Push أو تدقيق قرار تحديث PWA. دورات المصادقة ووظائف الخلفية الأصلية لم تُستبدل.

## التحقق

نجحت **422 حالة معزولة**:

- 14 اختبار Node لدور المراقب: الحراس الأصلية، الهوية الفعلية، الاستدعاء الداخلي، الطلبات المجمعة وHTTP داخل الذاكرة، رفض الاستيراد والتصدير، منع SQL الكتابي، معاملة Drizzle الحقيقية فوق درايفر وهمي، نطاق PMV2 والتزامن وبقاء الأدوار السابقة.
- 12 اختبار واجهة: صفحات Users وSites وReports الأصلية، تطابقها مع الأدمن تحت البيانات نفسها، حسابات ورسوم التقارير، نماذج الروابط المباشرة، تعطيل الأزرار والروابط والـportals واستعادة الحالة عند إزالة الحماية، والرابط الوسيط الحقيقي للـAPI.
- 74 اختبار صلاحيات مركزي سابق.
- 226 اختبار Node لمسارات التذاكر والفرق والمواد والمخزون والمشتريات والتكاليف والتحسين الحالية.
- 57 اختبار واجهة لمسارات مواد التذاكر وPMV2 والإضافة التخزينية الحالية.
- 39 اختبارًا سابقًا لتنفيذ PMV2 والصلاحيات والعضوية الفعلية والاستلام والأدلة. تحدّثت قائمة حقن الاستيرادات النقية في حاضنة الاختبار فقط لدعم ملفات الحماية الجديدة؛ بقيت تحققاته الأصلية.

تحويل صيغة ملفات التشغيل الـ32 نجح دون تحميل التطبيق. مقارنة TypeScript: **663 تشخيصًا قبل التصحيح وبعده، دون جديد أو محذوف**. الفحص العام ليس ناجحًا بسبب أخطاء المشروع السابقة. النسخ السابقة، وكتالوج الإجراءات، والنتائج، والبصمات محفوظة في `tools/observer/artifacts/correction` داخل المشروع.

لم يتصل الوكيل بقاعدة البيانات، ولم يشغّل التطبيق أو ينفّذ SQL، ولم يقرأ أو يعدّل Copy (2).

## القاعدة والاختبار العملي

المستخدم أضاف `observer` يدويًا، وملف نتيجة التحقق المرسل يؤكد وجوده في نهاية ENUM. **لا أوامر قاعدة إضافية لهذا التصحيح، ولا حاجة لعكس إضافة الدور.**

1. شغّل النسخة المعدلة من CMMSFINAL في بيئتك، وافتح جلسة مستقلة لحساب مراقب نشط.
2. افتح المستخدمين والتذاكر وطلبات الشراء والمخزون والتقارير وPMV2 والإنشاءات؛ يجب أن ترى الصفحات الأصلية وشارة «استعراض فقط».
3. اختبر البحث والفلاتر والتبويبات والتنقل للتفاصيل. رسوم وحسابات التقارير هي الأصلية.
4. تحقق من تعطيل الإضافة والتحرير والحذف والاعتماد والاستيراد والتصدير والطباعة والتنزيل. اكتب `/tickets/new` أو رابط تحرير مستند: تبقى الحقول الأصلية ظاهرة ومعطلة.
5. بحساب المراقب فقط، استدعاء API للتعديل أو الاستيراد أو التصدير يجب أن يُرفض دون تغيير السجل. تعديل الدور في جسم الطلب أو كتابة رابط لا يمنح صلاحية.
6. افتح جلسة أدمن وفني ومستودع مستقلة، واختبر إجراءً معتادًا لكل دور. لا تختبر محاولة تعديل فعلية بحساب إداري بقصد إثبات منع المراقب.
