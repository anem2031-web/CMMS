# صفحة الصيانة الخارجية المستقلة، إصلاحات أداء دورة الشراء، وإعادة تصميم صفحة "أصنافي"

تاريخ التنفيذ: 2026-08-05

## 1. صفحة الصيانة الخارجية (المسار C)

### 1.1 صفحة مستقلة بالقائمة الجانبية

كانت أدوات الصيانة الخارجية (تجهيز/استلام/تسليم أصول المسار C) تبويبًا مدمجًا داخل صفحة "دورة الشراء" (`/purchase-cycle`)، ظاهرًا فقط لحساب المستودع. أصبحت الآن صفحة مستقلة بمسارها الخاص:

```text
client/src/pages/purchase/ExternalMaintenance.tsx     ← صفحة جديدة (غلاف حول المكوّن القديم)
client/src/App.tsx                                    ← تسجيل المسار /external-maintenance
client/src/components/layout/DashboardLayout.tsx      ← رابط بالقائمة الجانبية مباشرة بعد "دورة الشراء"
client/src/pages/purchase/PurchaseCycle.tsx            ← إزالة التبويب المدمج القديم (لا ازدواجية)
shared/roles.ts                                        ← إضافة /external-maintenance لقوائم الحجب
                                                           (نفس الأدوار المحجوبة أصلاً عن /purchase-cycle)
client/src/i18n/ar.ts, en.ts, ur.ts                     ← مفتاح ترجمة nav.externalMaintenance
```

المكوّن الفعلي الذي يعرض البيانات (`ExternalMaintenanceWarehouseTab.tsx`) لم يتغيّر منطقه في هذه الخطوة — فقط انتقل من "تبويب داخل صفحة أخرى" إلى "صفحة مستقلة"، مع بقاء نفس الصلاحيات (`warehouse` / `owner` / `admin`).

الصفحة تعرض فقط بلاغات مسار C حصرًا، لأن الاستعلام الأساسي (`listPathCTicketsWaitingWarehousePreparation`) يشترط صراحة:

```ts
eq(tickets.maintenancePath, "C"),
eq(tickets.status, "work_approved"),
isNull(externalMaintenanceJobs.id)
```

### 1.2 إصلاح جدول `external_maintenance_jobs` المفقود بقاعدة البيانات

عند أول اختبار فعلي، ظلت صفحة الصيانة الخارجية عالقة على "جاري التحميل..." بلا نهاية. السبب: جدول `external_maintenance_jobs` لم يكن منشأً فعليًا بقاعدة البيانات رغم وجود ملف الترحيل بالمشروع:

```text
drizzle/migrations/2026_08_04_path_c_external_maintenance_workflow.sql
```

تم تنفيذ محتوى هذا الملف مباشرة على قاعدة البيانات (`CREATE TABLE IF NOT EXISTS external_maintenance_jobs ...`)، فحلّت المشكلة فورًا. لا تغيير بالكود هنا — الكود كان صحيحًا، والقصور كان بتنفيذ الترحيل نفسه على القاعدة الفعلية.

### 1.3 إعادة تصميم وثائق الطباعة

الملف: `client/src/lib/printExternalMaintenanceDocument.ts`

الوثائق الثلاث (تصريح خروج / استلام عودة / تسليم لإعادة التركيب) أُعيد بناؤها بالكامل:

- **جداول `<table>` رسمية حقيقية** بدل شبكة `div` — بيانات البلاغ/الأصل/المندوب/المستودع بعمودين من الأزواج (عنوان/قيمة)، بحدود وخلفية للعناوين.
- **قسم الحراسة والتوقيعات** كجدول فعلي بخانات فارغة للتعبئة اليدوية، بدل أسطر منقطة.
- **ضغط شامل ليتسع لصفحة A4 واحدة**: خط أصغر، تباعد أقل، صورة الأصل مصغّرة (110px بدل 270px)، بدل ما كانت الوثيقة تفيض لأكثر من صفحة.
- **إخفاء حقول موافقة الحراسة على الخروج** (الاسم/الوقت/حامل الأصل) بالكامل من الوثيقة طالما لم يعتمد الحارس الخروج فعليًا بالنظام، مع شريط تنبيه بديل "⏳ بانتظار اعتماد الحراسة لخروج الأصل بالنظام". تظهر البيانات تلقائيًا عند إعادة عرض/طباعة نفس الوثيقة بعد الاعتماد، لأنها مرتبطة فعليًا بحقل `gateExitApprovedAt`.

### 1.4 تبويبات + ترقيم (15/صفحة) + خط زمني للمراحل

الملف: `client/src/pages/purchase/ExternalMaintenanceWarehouseTab.tsx`

- الأقسام الأربعة (بانتظار التجهيز للخروج / عادت وبانتظار الاستلام / بانتظار التسليم للتركيب / متابعة المسار C) تحوّلت من أقسام مكدّسة عموديًا إلى **تبويبات حقيقية** (`Tabs`/`TabsList`/`TabsTrigger`)، كل تبويب معه عداد.
- كل تبويب **مرقّم صفحات** (`PAGE_SIZE = 15`)، بنفس مكوّن الترقيم المستخدم لاحقًا بصفحة "أصنافي" (السابق / أرقام / … / التالي، مع عرض أول وآخر رقم صفحة دائمًا).
- تبويب "متابعة المسار C" يعرض **خطًا زمنيًا فعليًا لكل بلاغ** (10 مراحل من `shared/externalMaintenanceWorkflow.ts`، من تجهيز المستودع حتى الإغلاق)، بنفس أسلوب الخط الزمني الموجود مسبقًا بصفحة تفاصيل البلاغ (دوائر ✓ متصلة بخطوط)، مع عرض تاريخ إتمام كل مرحلة إن وُجد.

## 2. إصلاح أداء صفحة دورة الشراء (يمس المسارات A + B + C لأنها نفس الصفحة)

### 2.1 المشكلة: استعلامات N+1

أربع نقاط بصفحة `/purchase-cycle` (تسعير، شراء، مستودع، إدخال مخزون) كانت تُثري كل بند شراء ببيانات (طلب الشراء / البلاغ المرتبط / سجل الصيانة الخارجية) عبر **رحلة قاعدة بيانات منفصلة لكل بند على حدة**، بعضها بالتوازي (`Promise.all`) وأسوأها (`pendingEstimateItems`) بحلقة `for` متسلسلة بلا أي توازي — أي حتى 3-4 رحلات متتابعة لكل بند. مع عشرات البنود ومع قاعدة بيانات سحابية بعيدة (TiDB Cloud)، هذا كان يترجم لثوانٍ من التأخير المحسوس.

### 2.2 الحل: استعلام JOIN مجمّع واحد

الملفات:

```text
server/_core/db/purchase.ts                    ← إضافة getPurchaseOrderTicketContextBatch
server/routers/purchase/purchase-orders.router.ts ← استبدال enrichPurchaseCycleItem (لكل بند)
                                                    بـ enrichPurchaseCycleItemsBatch (دفعة واحدة)
```

دالة جديدة واحدة (`getPurchaseOrderTicketContextBatch`) تجيب بيانات (طلب الشراء + البلاغ + سجل الصيانة الخارجية) لكل البنود المطلوبة **بضربة JOIN واحدة**، ثم تُبنى النتائج محليًا بالذاكرة (`Map`) بدل أي رحلة إضافية. طُبّق هذا على الأربع نقاط كلها (`pendingEstimateItems`, `pendingPurchaseItems`, `pendingWarehouseItems`, `pendingDeliveryItems`)، مع تعليق معماري صريح بالكود يوجّه أي تطوير مستقبلي لاستخدام نفس النمط بدل حلقة `await` لكل بند.

## 3. إعادة تصميم بطاقة الصنف — صفحة "أصنافي" (my-items)

الملف: `client/src/pages/inventory/MyItems.tsx`

بطاقة الصنف بكل التبويبات الأربعة (بانتظار التسعير / معتمد / تم الشراء / مستلم) أُعيد تصميمها بالكامل لمعالجة تشتت واضح بالعرض:

- **صورة الأصل**: كانت شريطًا ممطوطًا كامل العرض (`h-24 w-full object-cover`) يقصّ الصورة الأصلية لشريط رفيع غير مفهوم. صارت **صورة مصغّرة مربّعة ثابتة الحجم** (80×80) تعرض الصورة كاملة وواضحة.
- **بيانات الكمية / رقم الطلب / التكلفة / الإجمالي**: كانت 4 صناديق رمادية منفصلة تاخذ صف كامل. صارت **سطر نصي واحد مضغوط** متتالي.
- **زر الإجراء**: كان شريطًا ملوّنًا بعرض الشاشة كامل. صار **زرًا بحجمه الطبيعي** بجانب المعلومات.
- **الحالات غير التفاعلية** ("تم الشراء" / "مستلم" — بلا أي إجراء أصلاً) صارت `Badge` مضغوطة بدل شريط ملوّن كامل العرض.

النتيجة: ارتفاع البطاقة الواحدة أقل بكثير، ما يقلّل التمرير اللازم لعرض نفس عدد الأصناف.

### ترقيم صفحات "أصنافي" (كان موجودًا مسبقًا، بلا تعديل)

للتوضيح: صفحة "أصنافي" كانت أصلًا تحتوي — قبل أي تعديل بهذه الجلسة — على استعلام سيرفر مفلتر بالحالة (`getMyItemsPageItems`، لا `N+1` ولا جلب غير محدود) وترقيم عرض (`PAGE_SIZE = 15`) بنفس أسلوب صفحة الصيانة الخارجية. لم تُمس هذه الآلية، فقط بطاقة العرض (القسم أعلاه).
