# اختيار صنف احتياج المواد بنفس نافذة طلب الشراء

تاريخ التنفيذ: 2026-10-13. موافقة المستخدم: «نفذ الان». المجلد المصرح: `C:\Users\mh\Desktop\CMMSFINAL` فقط.

## قبل وبعد

| قبل | بعد |
| --- | --- |
| قائمة اختيار محدودة وحقل بحث مستقل أسفل بطاقة احتياج مواد التذكرة | زر «تحديد الصنف من الكتالوج» يفتح نفس نافذة إنشاء طلب الشراء |
| نافذة طلب الشراء محلية داخل صفحته | مكون مشترك واحد تستخدمه صفحة إنشاء الطلب وبطاقة الاحتياج |
| بحث المستودع يستدعي مصدر بطاقة التذكرة عند الكتابة | نفس بحث الكتالوج على الخادم وتأخير 350ms بعد توقف الكتابة، وشجرة التصنيفات و80 نتيجة كنافذة الشراء الأصلية |
| الاختيار يظهر من القائمة | الاختيار من نتيجة باسم الصنف ووصفه/وحدته وصورته عند توفرها وكوده، ثم يظهر المختار في البطاقة |

## ما بقي كما هو

- البحث والتصنيفات وأسماء الكتالوج وحجم النافذة وطريقة اختيارها مأخوذة من نافذة إنشاء طلب الشراء الحالية؛ لا هوية بصرية جديدة.
- اختيار الصنف محلي في نموذج المطابقة؛ **لا يحفظ المطابقة ولا ينشئ طلب شراء تلقائيًا**. الملاحظة الإلزامية وزر «تأكيد المطابقة» يبقيان، بنفس API والمعرفات والمراجعة ومفتاح العملية.
- وحدة الصنف يجب أن تطابق وحدة الاحتياج تمامًا. نافذة المطابقة تصفي النتائج حسب الوحدة، ويعيد الخادم فحصها وفحص نشاط الصنف والوحدة كما كان، دون تحويل وحدات تلقائي.
- كمية الفني ثابتة، وإضافة المستودع والإجمالي والألوان والحسابات باقية. الاختيار لا يمسح الإضافة أو الملاحظة، ولا يختار صنفًا لاحتياج آخر.
- بعد تأكيد المطابقة تتبع البطاقة مسار التوفير والتحويل أو شراء العجز الحالي. الصرف والاستلام والمرتجع واللوتات والتكلفة والورك فلو الحالي لم تُعدّل.
- لا طلبات كتالوج إضافية من البطاقة قبل فتح النافذة. مصدر الكتالوج العام الموجود يفحص صلاحيات القراءة؛ خدمة مطابقة التذكرة تحتفظ بحارسها. لا تعديل للحراس أو صلاحيات الأدوار.
- البلاغ المغلق يبقى محظور التنفيذ؛ لم يُفتح أو يُعدّل أي بلاغ لتجاوز هذا القيد.

## ملفات التشغيل

ثلاثة فقط:

| الملف | التعديل |
| --- | --- |
| `client/src/components/catalog/CatalogPickerDialog.tsx` | جديد: نقل نافذة الشراء الأصلية لمكون مشترك، مع خيار تصفية الوحدة للمطابقة فقط |
| `client/src/pages/purchase/CreatePurchaseOrder.tsx` | استيراد المكون المشترك بدل تعريفه المحلي؛ باقي النموذج ومنطق الحفظ والاختيار مطابقان للنسخة المحفوظة قبل التعديل |
| `client/src/pages/maintenance-teams/ExecutionPanel.tsx` | استبدال القائمة والبحث بزر فتح النافذة، وتخزين اختيار مستقل لكل احتياج، وإرساله لنفس تأكيد المطابقة |

لا تعديل خادم أو قاعدة أو مخطط أو PMV2 في هذه المهمة. تغيرت ملفات اختبارات/حاضنة وتوثيق داخل المشروع أيضًا. النسخ قبل التعديل والبصمات محفوظة في `tools/catalog-picker/artifacts/before.json` وملفات `.before`.

**المخاطرة منخفضة إلى متوسطة:** نقل مكون يستخدمه إنشاء طلب الشراء يقتضي التحقق من الاستدعاء والاعتماديات؛ اختبار المطابقة النصية أكد أن باقي الصفحة لم يُغيّر. المطابقة تستخدم نفس عقد الحفظ وموانع الخادم، لكن يلزم اختبار المستخدم على بيانات بيئته.

## التحقق

نجحت **72 حالة** معزولة عبر `node tools/catalog-picker/run.mjs`:

- 15 للمكون المشترك وربطه: البحث بعد 350ms، التصنيف وأبناؤه، اللغات الثلاث، الوحدة المطابقة، إغلاق الاختيار، عدم الحفظ قبل التأكيد، نقل معرف الصنف والملاحظة إلى API الأصلي، استقلال الاحتياجات، وبقاء 5 + 3 = 8.
- 15 لحقول الإضافة وبطاقات المستودع، و15 لمواد الفني، و10 لتبويب المستودع وPMV2، و17 لإجراءات التنفيذ الحالية.
- أحد الاختبارات يقارن باقي ملف إنشاء طلب الشراء بنسخته الأصلية حرفيًا بعد إخراج النافذة وتعديل الاستيرادات اللازمة فقط؛ لا تغيير في منطق النموذج.
- حاضنة الاختبار تمنع تحميل اتصال القاعدة والإعدادات الحية وتعطل قراءة ملفات البيئة. API والبيانات وهمية.
- TypeScript: **663 تشخيصًا قبل وبعد، introduced=[] وresolved=[]**. الفحص العام يبقى غير ناجح بسبب الأخطاء السابقة.
- معاينة متصفح ثابتة من مكونات البرنامج وCSS الحالي ببيانات وهمية: النافذة داخل بطاقة المادة، بعرض 672px الأصلي، وشجرة التصنيفات وحقل البحث ونتيجة الصنف والكود. التفاعل اختُبر بالحاضنة، دون جلسة أو قاعدة حية.

السجلات والصورة: `tools/catalog-picker/artifacts/tests.log` و`typecheck-comparison.json` و`picker-preview.jpg`. خدمة معاينة HTML/CSS المؤقتة تُوقف بعد الفحص؛ ليست تشغيلًا للتطبيق أو اتصالًا بالقاعدة.

## الاستخدام بعد إعادة تشغيل نسختك

1. افتح تبويب «تذاكر الصيانة» في `/scheduled-maintenance/warehouse-requests`، واختر احتياجًا غير مطابق لتذكرة نشطة.
2. اضغط «تحديد الصنف من الكتالوج» في قسم الإجراء. تظهر نافذة الشراء نفسها.
3. ابحث بالاسم أو الكود، أو اختر التصنيف من الشجرة، ثم اضغط نتيجة الصنف المطابق. تظهر نتائج وحدة الاحتياج فقط في سياق المطابقة.
4. تُغلق النافذة ويظهر الصنف المختار في البطاقة؛ تحقق أن كمية الفني وإضافة المستودع والإجمالي باقية.
5. اكتب ملاحظات المطابقة واضغط «تأكيد المطابقة». بعدها تظهر إجراءات التوفير الحالية حسب الرصيد والحالة.

**لا اتصال مباشر بالقاعدة أو SQL منفذ عليها أو تغيير بيانات/مخطط، ولا أوامر SQL يدوية مطلوبة. لم يُشغَّل التطبيق المتصل بالقاعدة ولم يُقرأ أو يُعدّل أو تُنقل ملفات إلى Copy (2).**
