# تقرير ربط إدارة فرق الصيانة — 2026-10-08

تم تنفيذ ربط إدارة «فرق الصيانة» فقط بعد الموافقة الصريحة. أُضيفت صفحة `/maintenance-teams` تحت الأصول في قائمة الإدارة، وخدمة API مستقلة `maintenanceTeams`. الربط التشغيلي لفرز التذاكر وإجراءات الفني والمواد ليس ضمن هذه الخطوة.

## ما أصبح موجودًا في الكود

- إضافة فريق باسمه واختيار مستودع فرعي **قائم ونشط**، دون إنشاء مستودع أو نسخ فرق PMV2.
- ربط الفريق بالفنيين الموجودين في `users`، بشرط أن يكون المستخدم فنيًا داخليًا نشطًا. إعادة العضوية تستخدم السجل نفسه وتحافظ على تاريخ الانضمام.
- عرض الفرق، البحث عن الفنيين، تفعيل الفريق وتعطيله. الحسابات التي تعطلت أو تغير دورها تبقى ظاهرة عندما تكون مرتبطة لتتيح فك الربط.
- منع تعطيل فريق لديه تنفيذ مفتوح، ومنع إزالة آخر فني صالح منه. تُقفل صفوف الفريق قبل تغيير العضوية لمنع إزالة العضوين الأخيرين بالتزامن داخل هذه الخدمة.
- السماح للإدارة فقط: المالك، المدير العام للنظام، مسؤول الصيانة، مسؤول الصيانة العامة. الحماية في الصفحة ومسار الوصول وإجراءات الخادم؛ هوية الفاعل مصدرها جلسة الخادم، ويُرفض تمريرها من العميل.
- تسجيل الإنشاء والتفعيل والعضوية في **سجل التدقيق القائم `audit_logs`** داخل المعاملة نفسها. فشل التدقيق يمنع حفظ التغيير.
- دعم واجهة عربية وإنجليزية وأردية. بيانات المعاينة الوهمية منفصلة عن صفحة التطبيق؛ لا يوجد بديل وهمي عند تعذر القاعدة.

## قاعدة البيانات

أنشأ صاحب المشروع الجداول التسعة يدويًا، وقد راجعت نتائج CSV المحلية المرسلة. **لم أفتح اتصالًا بقاعدة البيانات، ولم أقرأ منها أو أكتب إليها، ولم أشغّل التطبيق الرئيسي أو أنفذ migration. لا توجد أوامر SQL إضافية لهذه الخطوة.**

عندما تختبر أنت الصفحة في تطبيقك، فإن API الجديدة مصممة للقراءة من الفرق والعضويات والفنيين والمستودعات؛ التعديل محصور في `maintenance_teams` و`maintenance_team_members` وسجل التدقيق. يوجد استعلام قراءة على `ticket_team_assignments` لحماية الفرق المرتبطة بتنفيذ مفتوح. لا تُعدل المستخدمين أو المستودعات أو التذاكر أو المخزون أو جداول PMV2.

- اختبارات المعاملات والقفل هي محاكاة وفحص SQL؛ لا تثبت تشغيل MySQL الحقيقي أو نجاح الصرف أو الشراء أو المرتجع الفعلي.

## درجة المخاطرة والخطوة التالية

المخاطرة من الإضافة **محدودة ومتوسطة إلى حين اختبار التشغيل الفعلي**: أُضيفت صفحة وخدمة جديدة مع نقاط تسجيل قليلة، لكن استعلامات القاعدة والمعاملات لم تُجرب على MySQL احترامًا للمنع. لا أضمن انعدام الأعطال. لا يحتاج هذا الإنجاز تغيير schema أو خدمات المخزون القائمة.

التالي أن تختبر أنت صفحة «فرق الصيانة» بحساب مسؤول مخوّل في تطبيقك: إضافة فريق باسم فريد ومستودع فرعي قائم، ربط فني موجود، تحديث الصفحة للتحقق من الحفظ، تعطيل الفريق وإعادة تفعيله والتحقق من التدقيق. بعد نتيجتك وموافقتك الصريحة ننتقل إلى ربط **الفرز حسب الفريق**؛ الإسناد بالاسم يبقى كما هو. لا يبدأ ربط تنفيذ الفني والمواد قبل إنهاء واختبار نقطة الإسناد.

عند إضافة موصل الإسناد لاحقًا، يجب أن يقفل صف الفريق نفسه داخل معاملة الإسناد قبل التحقق من نشاط الفريق وعضويته؛ حتى لا يتسابق إسناد جديد مع تعطيل الفريق أو إزالة عضويته.
