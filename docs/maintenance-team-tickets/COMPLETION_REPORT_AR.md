## حدود النتائج

- هذه اختبارات منطق وخدمات محاكاة. لا تثبت معاملات/أقفال TiDB أو الترحيل الفعلي للمخزون أو توافق DDL مع القاعدة المنشورة.
- لا توجد طبقة تخزين دائمة أو API مسجل في النظام الحالي. المعاينة تحفظ البيانات في الذاكرة وتفقدها عند تحديث الصفحة.
- مؤثرات الصرف والتحويل والشراء والمرتجع في testing/memory-store.ts وهمية صريحة، ولا تستخدم بديلًا تشغيليًا عن الخدمات الحالية.
- دورة C الفعلية لم تعدل ولم تختبر. زر المحاكاة يمثل وصول حدث اكتمال الدورة وتسليم الأصل، ولا يختصرها في الإنتاج.
- اعتماد نتيجة الفريق لا يغلق التذكرة الحالية. الحقول والأحداث اللازمة لتحديث البند والرأس تتطلب المرحلة التالية.
- الكميات أعداد صحيحة؛ توسعة الكميات الكسرية أو وحدات بديلة ليست ضمن هذه المرحلة، مراعاة لشكل سندات الصرف والمرتجع المرسل من صاحب المشروع.
- لا اختبارات شاملة للمشروع الحالي أو تشغيل خادمه أو تنفيذ migrations/db:push؛ لم نحتاج ذلك لاختبار الطبقة المعزولة.

## أوامر القاعدة المعدة

راجع [شرح الأوامر](DATABASE_COMMANDS_AR.md). الحزمة تتضمن:

1. أمر فحص قراءة فقط 00_preflight؛ المتوقع صفر جداول بالمسميات المقترحة.
2. تسعة أوامر CREATE لجداول جديدة مرتبة حسب الاعتماد بينها، مع تسعة أوامر SHOW CREATE مستقلة للتحقق.
3. أمر تحقق نهائي بالقراءة فقط؛ المتوقع تسعة جداول.

ليس هناك تعديل أو تنظيف أو نقل بيانات للجداول الحالية أو جداول PMV2. التنفيذ يدوي بواسطة صاحب المشروع: أمر واحد ثم نتيجته ثم مراجعتها قبل التالي. **الأوامر لم تنفذ، ولا نسجل الجداول كمنشأة قبل استلام النتائج.**

**نقطة التوقف:** مرحلة البناء والاختبارات المستقلة مكتملة. لا يبدأ ربط أو إصلاح ملفات النظام الحالي حتى يراجع صاحب المشروع التقرير ويوافق صراحةً على المرحلة التالية. حظر اتصال الوكيل بقاعدة البيانات مستمر بعد هذه الموافقة أيضًا؛ أي SQL ينفذه صاحب المشروع يدويًا.

- الاستخدام يسجل مرة لكل صنف مع اسمه ووحدته والمطلوب والمصروف، ويبقى الافتراضي كامل المصروف. تفاصيل الإصلاح إلزامية حسب قرار صاحب المشروع.

- مراجعة الرصيد لا تصرف أو تغير الحالة. الصرف يتطلب تأكيدًا صريحًا، مع فحص الرصيد داخل معاملة المحاكاة عند التنفيذ. تأكيد الاستلام موجود كذلك بعد توفير النقص.
- يبدأ اختيار المادة فارغًا؛ أزيل المعرف 101 من واجهة الفني.
- العبارة النهائية «اكتمل تنفيذ الفريق». لا تغير إغلاق التذكرة الأصلية، ولم يضف اعتماد استخدام جديد للمسؤول.
