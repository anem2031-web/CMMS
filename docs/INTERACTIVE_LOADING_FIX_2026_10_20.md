# تقليل انتظار الكتالوج والشراء وتفاصيل التحسين — تنفيذ محلي

## الملاحظة الحية قبل التعديل

وثقت جولات المتصفح بحساب RED9 انتظار أول فتح لاختيار الكتالوج داخل شراء حتى 20–28 ثانية، وتفاصيل فكرة التحسين حتى نحو 36 ثانية ثم لوحة التنفيذ حتى نحو 43 ثانية. القائمة العامة لطلبات الشراء تأكدت عند نحو 20 ثانية. هذه حدود رصد مرئية تقريبية، لا تحليل زمن SQL أو إثبات نسبة مساهمة كل سبب. لم يتكرر بطء الكتالوج بنفس الشدة في كل محاولة.

## ما ثبت من المصدر وما تغير

1. **حجب نتائج سريعة خلف حزمة HTTP:** كان `httpBatchLink` يجمع قراءات متزامنة، وينتظر استجابة الحزمة كاملة. أضيف ناقل `createReadTransport` يوجه القراءة التي تطلب `independentReadOptions` إلى `httpLink`، وتبقى البقية في الناقل المجمع. طبق الاختيار على قراءات نافذة الكتالوج (الأصناف/التصنيفات/الوحدات)، وعلى قراءات قائمة الشراء الأساسية وبطاقات/دفعات إجراء المراجع، وتفاصيل التحسين ولوحة التنفيذ. لم يتحول التطبيق كله إلى طلبات منفصلة.
2. **تكرار تسلسل تفاصيل التحسين:** كان `getById` يحسب الإنجاز من شجرة المستندات، وبعد وصوله تُركب لوحة التكاليف وتقرأ الشجرة مرة أخرى. أضيف خيار `includeExecutionProgress:false` لهذا العرض فقط؛ يحافظ الاستدعاء المعتاد على حساب الإنجاز الحالي. تظهر بيانات الفكرة أولًا، وتعرض لوحة التنفيذ النسبة الحية بعد إكمال قراءتها، دون عرض 0% مصطنع أثناء الانتظار.
3. **رحلات زائدة داخل الشجرة:** أصبحت قراءة الأبناء تعيد الحقول اللازمة مباشرة بدل إعادة قراءة الصفوف بمعرفاتها عند المستوى التالي. شجرة رأس وفرع تتطلب 3 قراءات تذاكر بدل 4 في كل من قارئ الإنجاز والملخص. التفرعات والمهام الجديدة والمستندات المفقودة والتكاليف والمرتجعات وقواعد الإغلاق لم تتغير؛ تبقى حدود الدورات/العمق/الحجم، وقراءات التذاكر مقسمة حتى 500 معرف.
4. **إخفاء نتائج مخزنة أثناء تحديثها:** نافذة الكتالوج تحتفظ بصفوف نفس مفتاح البحث أثناء تحديث خلفي، مع إبقاء مؤشر تحديث صغير؛ الأخطاء ورفض الصلاحية يظلان واضحين، ولا تعرض صفوف مخزنة عند رفض قراءة الأصناف. لا `staleTime` جديد أو ذاكرة صلاحيات مشتركة.

## حدود الصلاحيات والعمل

- رابط المراقب يبقى قبل ناقل HTTP. الاستدعاء المستقل لا يتجاوز أي API أو حارس خادمي.
- ملفات الكوكيز وSuperJSON محفوظة. `independentRead` لا يغير ناقل أي mutation حتى لو أرسله العميل عليها.
- صلاحيات قراءة الفكرة وتنقية بيانات الموظف تبقيان قبل إرجاعها، والتحقق من طلبات الشراء في ملخص التنفيذ محفوظ.
- لم تتغير الكتابات المالية/المخزنية أو الاعتمادات أو شروط PDF. لا SQL أو ترحيل أو أعمدة أو متغير تفعيل لهذا الإصلاح، ولا اتصال بقاعدة أو نشر.
- الطلبات المستقلة قد تزيد عدد اتصالات HTTP مقارنة بالحزمة؛ لذلك طُبقت على القراءات التفاعلية المحددة، دون زيادة إعادة المحاولات أو تكرار دوري.

## ما يحتاج التحقق بعد النشر

لم ننسب أزمنة Railway إلى SQL أو الشبكة بدقة، ولم نضمن زوال كل تأخير. يلزم بعد نشر الكود إعادة قياس أول فتح لنافذة الاختيار والبحث والاختيار والرصيد، وقائمة الشراء، وتفاصيل IMP-2026-00016 ولوحة تنفيذها، بنفس الحساب وحالة بيانات مقاربة. إذا بقي الانتظار، تُقاس مدد استعلامات الخادم والخدمات الخارجية؛ لا نحذف حراس الوصول لمعالجته.

قوائم الشراء العامة القديمة لم تتحول في هذا التعديل إلى ترقيم صفحات خادمي، وتاريخ حركات المخزون الكامل لم يُعد تصميمه. تبقى بنود الاختبار السابقة والسجلات التاريخية المؤجلة كما هي.
