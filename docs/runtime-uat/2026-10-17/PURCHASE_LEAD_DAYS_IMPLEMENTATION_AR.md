## قرارات التنفيذ

- العمود الجديد `purchase_order_items.deliveryLeadDays` اختياري؛ السجلات القديمة تبقى NULL ولا يجرى أي ترحيل لتواريخها.
- تبقى مدة البداية أربعة أيام، مثل السلوك الافتراضي السابق، ويمكن تغييرها لكل صنف. التحقق يقبل أعدادًا صحيحة من 0 إلى 3650؛ الصفر يعني يوم الإرسال، وليس قيمة مفقودة.
- التاريخ في نموذج الإعداد معاينة بافتراض الإرسال اليوم. تعرض الشاشة بوضوح أن الحفظ لا يبدأ المدة. التاريخ غير قابل للتعديل يدويًا.
- عند إنشاء طلب مرسل مباشرة، تستخدم الأصناف والرأس لحظة إرسال واحدة. يشمل ذلك أصناف نموذج طلب مواد التذكرة وPMV2؛ الهوية والكميات وروابط الاحتياج تبقى كما هي.
- `submitDraft` و`updateDraft` يقفلان رأس الطلب ويعيدان التحقق من `draft`. يمنع ذلك إرسالًا مكررًا أو محررًا قديمًا من تغيير المهل بعد الإرسال. الفشل يعيد جميع الكتابات داخل المعاملة.
- تواريخ المسودات القديمة محفوظة إذا لم تُدخل مدة جديدة. عند إدخال مدة، يحسب تاريخ جديد من الإرسال؛ لا استنتاج تلقائي لمدة قديمة ولا إعادة كتابة تاريخية.
- يبقى API داعمًا لتاريخ قديم بلا مدة حتى لا تتعطل الخدمات والعملاء السابقون. إخفاء إنشاء الصنف اليدوي تعديل للواجهة المطلوبة، وليس تغييرًا لحوكمة كتالوج المواد أو صلاحيات API.
- منشئ الطلب من رأس `purchase_orders.requestedById` مع اسم المستخدم، وليس المندوب أو منشئ البلاغ. يقرأ عبر JOIN في استعلام أصناف المندوب نفسه، دون رحلة لكل صنف أو كشف حقول حساب حساسة.
- المتبقي محسوب من اليوم الحالي في الرياض؛ صفر = «مطلوب اليوم»، السالب = «متأخر…». يتحدث العد كل دقيقة ما دام حساب المندوب مفتوحًا.
- الفلاتر الحالية ورابط الصنف وحالات الشراء الجزئي ومراحل المراجعة والاعتماد بقيت كما هي. لا تغيير لقائمة أدوار الوصول.

## أوامر القاعدة — ينفذها المالك يدويًا

لم تُنفذ أي من الأوامر التالية، ولم يفتح الوكيل اتصالًا بقاعدة بيانات. الملف موجه إلى `copycmms` بالاسم الصريح. تنفذ كل عبارة وحدها.

**01 — فحص وجود العمود:**

```sql
SELECT TABLE_SCHEMA, TABLE_NAME, COLUMN_NAME, COLUMN_TYPE,
       IS_NULLABLE, COLUMN_DEFAULT
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = 'copycmms'
  AND TABLE_NAME = 'purchase_order_items'
  AND COLUMN_NAME = 'deliveryLeadDays';
```

**02 — إذا كانت نتيجة 01 فارغة فقط: إضافة مكان حفظ مدة التوريد.**

```sql
ALTER TABLE `copycmms`.`purchase_order_items`
  ADD COLUMN `deliveryLeadDays` INT NULL DEFAULT NULL AFTER `requiredDate`;
```

إذا كان العمود موجودًا، لا تعِد تنفيذ الإضافة؛ تحقق من أنه INT ويسمح بـNULL.

**03 — أعد عبارة 01 للتحقق.** المتوقع صف للعمود، النوع INT، و`IS_NULLABLE=YES` و`COLUMN_DEFAULT=NULL`.

يجب إضافة العمود قبل رفع نسخة الكود: قراءات بنود الشراء ستستخدمه بعد تحديث مخطط Drizzle. لا أوامر UPDATE أو Backfill، ولا جداول جديدة، ولا توليد/تنفيذ ترحيل آلي. التراجع التشغيلي يكون بإرجاع الكود السابق مع إبقاء العمود الاختياري؛ لا حاجة لحذف العمود أو بياناته.

- 175 اختبارًا معزولًا ناجحًا في عشرة ملفات؛ منها 70 اختبارًا جديدًا لحساب اليوم والمدة، والمسودة والإرسال والتعديل، والتراجع الذري عند الفشل، والتوافق القديم، وحالة المسودة المتزامنة، والصلاحيات، واستعلام المنشئ المقيد بالمندوب، والواجهة والفرز في اللغات الثلاث.
- اختبارات المشتريات تستخدم تخزينًا بديلًا بالذاكرة. استعلام SQL الخاص باسم المنشئ جرى عبر MySQL proxy بالذاكرة فقط. يمنع إعداد الاختبار تحميل ملفات الاتصال والبيئة الفعلية.
- مقارنة TypeScript: 662 تشخيصًا حاليًا مقابل 663 في خط الأساس، دون تشخيص جديد. عولج اختلاف طباعة نوع قاموس اللغات القديم وعدد خصائص المخطط المخفية في رسالتي خطأ قديمتين للمقارنة فقط؛ الأخطاء الأصلية لم تُخفَ أو تُصلح ضمن هذا التسليم. فحص المشروع الشامل ليس نظيفًا.
- تحويل بناء الملفات الاثني عشر نجح دون تحذيرات. فحص `git diff --check` ناجح.
- معاينة متصفح محلية باستخدام عنصر المدة الفعلي وبطاقة المندوب الفعلية وCSS البرنامج. تغيير المدة من 3 إلى 5 غيّر المعاينة من 20 إلى 22 أكتوبر. تحقق أن التاريخ للقراءة فقط، وأن البطاقات تعرض المتأخر ثم المطلوب اليوم ثم القادم، والأسماء والعد التنازلي ظاهرة بالعربية والإنجليزية والأردية. لا تجاوز أفقي في نافذة المتصفح الافتراضية.
- أُغلق تبويب المعاينة وأُوقف خادم العرض المحلي بعد التحقق. صفحة Railway وحساباتها لم تُستخدم أو تُعدّل بهذا التسليم.

1. تنفيذ أمر العمود يدويًا والتحقق من نتيجته.
2. رفع الكود إلى Railway بواسطة صاحب المشروع.
