# تنزيل PDF لحزمة التسعير بعد الإرسال فقط

نُفذ داخل `C:\Users\mh\Desktop\CMMSFINAL` فقط، بتفويض «نفذ الآن» بتاريخ 2026-10-18. لم يُتصل بأي قاعدة فعلية، ولم ينفذ SQL أو نشر Railway أو إرسال مالي حي.

| الجزء | قبل التعديل | بعد التعديل |
|---|---|---|
| الحزمة المفتوحة | زر معاينة وAPI يولدان PDF | لا زر تنزيل؛ API يرفض الطلب قبل جلب التوقيعات أو التوليد |
| إرسال الحزمة | ينتظر توليد PDF داخل معاملة الحسابات | يحفظ لقطة البيانات والتوقيعات مع دفعات الحسابات ذريًا، دون توليد PDF |
| تنزيل المستند | معاينة Blob داخل iframe المحظور بـCSP | تنزيل مباشر باسم الحزمة؛ حماية الإطارات لم تتغير |
| أول تنزيل بعد الإرسال | PDF سبق حفظه وقت الإرسال | يولد من اللقطة المحفوظة فقط، خارج معاملات SQL، ثم يحفظ البايتات |
| التنزيلات التالية | الملف المحفوظ | البايتات المحفوظة نفسها، بما يشمل الحزم المؤرشفة والملفات السابقة |
| فشل توليد PDF | يلغي إرسال الحزمة | يفشل التنزيل وحده؛ إعادة تنزيل لا تنشئ دفعات حسابات جديدة |
| زر الأرشفة | يظهر للمندوب بعد الإرسال | مخفي؛ السجلات المؤرشفة وإجراء الخادم القديم باقيان للتوافق |

## تفاصيل المحافظة على المسار

- `submitPricedBatchForPO` وموافقات الحسابات والإدارة لم تُعدل. تظل البنود المحددة ومراجع PR والحزم الأصلية والموقع والقسم والبلاغ داخل المعاملة الحالية.
- تثبيت اللقطة مع الإرسال يتضمن أسماء وأسعار وكميات ومراجع وتوقيعات المصادر. جلب الصور المتكررة مرة واحدة وبالتوازي؛ لا تؤجل قراءة التوقيعات المتغيرة إلى أول تنزيل.
- التفويض وملكية المندوب يفحصان لكل طلب تنزيل، حتى أثناء توليد متزامن. المراقب يبقى ممنوعًا من التصدير. البيانات المقروءة العادية لا تعرض البايتات أو التوقيعات.
- محاولات التنزيل المتزامنة في العملية الواحدة تتشارك التوليد. وعند تشغيل أكثر من نسخة خادم يحفظ تحديث مشروط أول ملف فقط ثم يعيد الجميع الملف المحفوظ، دون استبداله.
- حد الملف الحالي 8 MiB باقٍ. اللقطة المفقودة أو التالفة لا تستبدل بقراءة من البيانات الحية.
- استكمال الإشعارات وربط البلاغات وعلامة الاستكمال وإعادة المحاولة القائمة مستمرة. لم تتحول العمليات المالية إلى مهام خلفية غير محفوظة.
- بعد نجاح الرد تتحدث حالة الحزمة محليًا ويثبت اختيارها؛ إعادة جلب قوائم النظام لا تبقي زر الإرسال منتظرًا. يظهر نص انتظار واضح أثناء الإرسال وتجهيز PDF باللغات الثلاث.
- لا تغيير على حد عرض قائمة الحزم الحالي (آخر 200 حزمة)، أو بقية صفحات البرنامج، أو طباعة الباركود، أو ملفات مشروع آخر.

## الملفات التشغيلية المتأثرة

1. `server/services/delegate-pricing-bundles/service.ts`: حفظ اللقطة دون PDF عند الإرسال، منع التنزيل قبل الإرسال، والتوليد المؤجل الآمن وحفظ أول نسخة.
2. `client/src/pages/purchase/DelegatePricingBundles.tsx`: إزالة iframe والأرشفة من الواجهة، التنزيل بعد الإرسال، حالات الانتظار وتحديث النجاح الفوري.
3. `client/src/lib/downloadPricingBundlePdf.ts`: تنزيل بايتات الخادم عبر رابط مؤقت مع تحريره بعد بدء التنزيل.
4. `client/src/i18n/pricingBundles.ts`: نصوص العربية والإنجليزية والأردية.

## التحقق

- 43 اختبارًا ناجحًا في ثلاثة ملفات: الخدمة وRPC والتوافق مع دالة الحسابات الأصلية، الواجهة الفعلية باللغات الثلاث، والتنزيل المباشر وإدارة رابط Blob.
- تشمل الاختبارات: عدم استدعاء التوليد وقت الإرسال، رفض تنزيل المفتوحة عبر API، فشل التوقيعات قبل الإرسال، فشل PDF بعد الإرسال وإعادة تنزيله، التراجع عند فشل دفعة حسابات لاحقة، منع تكرار الإرسال، ثبات الأسعار والتوقيعات رغم تغير المصدر، وحماية المراقب والملكية والتزامن بين نسخ الخادم.
- TypeScript: 662 تشخيصًا قائمًا مقابل 663 في خط الأساس، ولا تشخيص جديد بعد التعديل. لا يُدعى نجاح فحص المشروع العام ذي الأخطاء السابقة.
- المتصفح: مكونات التطبيق الفعلية ببدائل محلية فقط، مع `frame-src 'none'` و`object-src 'none'`. لا PDF قبل الإرسال؛ بعد نجاح الرد يظهر «تنزيل PDF» ويختفي الإرسال والتعديل والأرشفة. تم تنزيل ملف تجريبي فعلي يبدأ بـ`%PDF-1.4` وعدده 608 بايت.
- تأخر إعادة الجلب في المعاينة ضُبط على 8 ثوانٍ؛ ظهر إجراء التنزيل خلال 327 مللي ثانية من ضغط الإرسال ذي الرد التجريبي بعد 150 مللي ثانية. هذا اختبار لترتيب واجهة النجاح فقط، وليس قياس أداء Railway أو الشبكة أو توليد PDF الفعلي.
- أدلة: `pricing-pdf-tests.json`، `pricing-pdf-typecheck.json` وملف التشخيصات الخام، `pricing-pdf-browser-check.json`، ومعاينة `pricing-pdf-open.jpg` في المجلد نفسه.
- أغلقت تبويبات المعاينة وخادمها؛ تبويب Railway الأصلي لم يُعدّل.

## القاعدة والتشغيل

**لا أوامر قاعدة جديدة مطلوبة.** يستخدم الكود عمودي `snapshotJson` و`pdfContent` الموجودين والقابلين لـNULL في جدول الحزم الذي جُهز سابقًا. لم يتغير المخطط أو التفعيل، ولم تُحدّث سجلات قديمة.

يلزم رفع الكود بواسطة صاحب المشروع ثم اختبار حزمة على `copycmms` فقط. عند أول تنزيل يتطلب التوليد عمل محرك PDF والتخزين الحاليين؛ عند تعذره تبقى دفعات الحسابات مرسلة ويمكن إعادة محاولة التنزيل.

لا يُنصح بإرجاع خدمة PDF إلى الإصدار السابق بعد إنشاء حزم مرسلة بـ`pdfContent=NULL`؛ الإصدار السابق يفترض وجود الملف. عند إيقاف الميزة يفضل إخفاء المسار بالعلم الحالي مع إبقاء هذا القارئ الداعم للتوليد المؤجل، والاحتفاظ بالجداول واللقطات والملفات.
