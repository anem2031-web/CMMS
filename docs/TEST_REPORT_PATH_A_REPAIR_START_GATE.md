# توثيق واختبار بوابة بدء الإصلاح — المسار A

**التاريخ:** 2026-08-03  
**النطاق:** صفحة تفاصيل البلاغ وإجراءات التنفيذ في الخادم  
**تغييرات قاعدة البيانات:** لا توجد

## السلوك المعتمد

بعد اعتماد نتيجة الفحص واختيار مسار الإصلاح `A` يصبح البلاغ في حالة `work_approved`، وفي هذه المرحلة يظهر **زر بدء الإصلاح فقط**.

لا يظهر القسم التالي قبل بدء الإصلاح:

- `📸 رفع صورة الإصلاح - المسار A`
- حقل ملاحظات الإصلاح
- زر رفع صورة بعد الإصلاح
- زر إكمال الإصلاح وإرساله للإغلاق

عند الضغط على **بدء الإصلاح** تنتقل حالة البلاغ إلى `in_progress`، ثم:

- يختفي زر بدء الإصلاح.
- يظهر قسم رفع نتيجة الإصلاح الخاص بالمسار `A`.
- لا يظهر نموذج الإكمال العام القديم بالتزامن مع نموذج المسار `A`.

## حماية الخادم

لم يقتصر التعديل على إخفاء القسم في الواجهة. إجراء `markReadyForClosure` يرفض الطلب ما لم يكن:

```text
maintenancePath = A
status = in_progress
```

وبذلك لا يمكن تجاوز زر بدء الإصلاح باستدعاء الـAPI مباشرة.

كما يمنع إجراء `completeRepair` العام استخدامه مع المسار `A`، حتى لا يتم تجاوز دورة الإغلاق الخاصة بهذا المسار.

## حالات الاختبار

| الحالة | زر بدء الإصلاح | قسم رفع صورة إصلاح A | نموذج الإكمال العام |
|---|---:|---:|---:|
| `work_approved` + المسار `A` | يظهر | مخفي | مخفي |
| `in_progress` + المسار `A` | مخفي | يظهر | مخفي |
| `in_progress` + المسار `B` | مخفي | مخفي | يبقى وفق السلوك السابق |
| مستخدم غير مخوّل | مخفي | مخفي | مخفي |

## نتيجة التحقق

- نجح فحص بناء الجملة للملفات المعدلة باستخدام مترجم TypeScript.
- نجحت اختبارات القواعد النقية للانتقال من `work_approved` إلى `in_progress`.
- نجح عقد التكامل الذي يتحقق من استخدام نفس القواعد في الواجهة والخادم.
- لم يتم تشغيل حزمة Vitest الكاملة لعدم وجود `node_modules` داخل نسخة المشروع المرفوعة.
