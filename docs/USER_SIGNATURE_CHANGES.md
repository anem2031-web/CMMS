# التوقيع الإلكتروني للمستخدمين

**التاريخ:** 2026-07-23

## الهدف
ربط كل مستخدم بصورة توقيعه، لتظهر تلقائيًا في خانة توقيعه داخل **وثيقة «طلب مشتريات وصرف عهدة مالية»** الصادرة بعد اعتماد الحسابات.

## النطاق المعتمد (حسب القرار)
التوقيع يظهر تلقائيًا في **ثلاث خانات فقط** بجدول «مسار الاعتماد والتوقيعات»:

| الصفة | المصدر | التوقيع |
|---|---|---|
| مقدّم الطلب | `po.requestedById` | ✅ تلقائي |
| مراجع الطلب | `po.reviewedById` | ✅ تلقائي |
| اسم مستلم العهدة | المندوب المسعِّر | ✅ تلقائي |
| الحسابات | `batch.accountingApprovedById` | ⬜ فارغة (توقيع يدوي) |
| رئيس الحسابات / الرئيس التنفيذي | غير مربوطة بمستخدم | ⬜ فارغة (توقيع يدوي) |

أي مستخدم بلا توقيع محفوظ تبقى خانته فارغة تمامًا كما هي اليوم — لا تغيير في شكل الوثيقة.

## الصلاحيات
رفع/استبدال/حذف التوقيع متاح لدور **`admin` و`owner` فقط**، ومفروض على الخادم (`updateSignature`) وليس بالواجهة وحدها. المسؤول يمكنه إدارة توقيع أي مستخدم بما فيهم نفسه.

## قرار تقني مهم: لماذا base64 وليس رابطًا
وثيقة الـPDF تُبنى بـPuppeteer عبر `page.setContent()`، وهي بلا عنوان أساس (base URL)، فالروابط النسبية مثل `/api/media?key=...` **لا يستطيع المتصفح داخل الخادم تحميلها** (وتحتاج مصادقة أيضًا). لذلك تُقرأ صورة التوقيع من التخزين مباشرة وتُضمَّن في الـHTML كـ`data:` URL — فيظهر التوقيع دائمًا بلا اعتماد على الشبكة أو الجلسة.

عند فشل قراءة الصورة لأي سبب، تبقى الخانة فارغة ولا تتعطل الوثيقة (`getSignatureDataUrl` تُرجع `""`).

## خطوة نشر مطلوبة
تشغيل الهجرة على قاعدة TiDB:

```sql
ALTER TABLE `users`
  ADD COLUMN `signatureUrl` varchar(500) NULL COMMENT 'رابط صورة التوقيع الإلكتروني للمستخدم';
```

التحقق:

```sql
SHOW COLUMNS FROM users LIKE 'signatureUrl';
```
