# توثيق واختبار متطلبات إكمال الإصلاح — المسار A

**التاريخ:** 2026-08-03  
**النطاق:** صفحة تفاصيل البلاغ وإجراء إرسال إصلاح المسار A للإغلاق  
**تغييرات قاعدة البيانات:** لا توجد

## السلوك المعتمد

بعد الضغط على **بدء الإصلاح** وظهور قسم:

`📸 رفع صورة الإصلاح - المسار A`

يبقى زر **إكمال الإصلاح - إرسال للإغلاق** معطلاً حتى يتحقق الشرطان معًا:

1. كتابة نص فعلي في حقل **ملاحظات الإصلاح**؛ المسافات وحدها لا تُقبل.
2. رفع **صورة بعد الإصلاح** بنجاح.

عند حذف الصورة بعد رفعها يعود الزر إلى الحالة المعطلة، وكذلك عند حذف نص الملاحظات.

## حماية الخادم

إجراء `markReadyForClosure` يتحقق من الملاحظات والصورة مرة أخرى قبل تغيير حالة البلاغ إلى `ready_for_closure`.

لذلك لا يمكن تجاوز الشرط باستدعاء واجهة API مباشرة أو باستخدام نسخة واجهة قديمة.

رسالة الرفض:

```text
يجب كتابة ملاحظات الإصلاح وإرفاق صورة بعد الإصلاح قبل إرسال البلاغ للإغلاق
```

## التحقق

- تم فحص تحويل TypeScript للملفات المعدلة دون أخطاء بناء جملة.
- أضيف اختبار مباشر للدالة `isPathARepairEvidenceComplete`.
- أضيف اختبار عقد تكامل يثبت استخدام القاعدة نفسها في الواجهة والخادم.
- لم تُشغّل حزمة Vitest الكاملة لأن `node_modules` غير موجودة داخل نسخة المشروع المرفوعة.
