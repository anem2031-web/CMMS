# تقرير اختبار دورة فحص البلاغات

التاريخ: 2026-08-03

## النطاق المنفذ

- إسناد الفني مباشرة دون قبول مهمة أو تسجيل بدء الفحص.
- إلزام تعيين فني مستخدم عند فرز بلاغ الصيانة العامة.
- تمكين الفني المسند إليه ومدير الصيانة العامة ومدير الإنشاءات والمشتريات والمشرف من تسجيل نتيجة الفحص ضمن نطاقهم.
- اعتماد نتيجة المدير تلقائيًا، وإرسال نتيجة الفني أو المشرف إلى مدير الجهة للمراجعة.
- حفظ منفذ الفحص الميداني ومدخل البيانات كمستخدمين مستقلين.
- دعم المسودة، الإرسال، الإعادة للتصحيح، الاعتماد، والمراجعات المتعاقبة.
- منع تحديد مسار التنفيذ قبل اعتماد نتيجة الفحص.
- تقييد إجراءات التنفيذ الفنية بالفني المسند إليه أو مدير الجهة المخول.

## قاعدة البيانات

ملف الترحيل:

`drizzle/migrations/2026_08_03_ticket_inspection_workflow.sql`

يضيف حقول دورة الفحص إلى `tickets` وحقول المراجعة ونسب التنفيذ/الإدخال إلى `inspection_results`. أوامر إضافة الأعمدة مفصولة لتوافق TiDB، مع ترحيل محافظ للسجلات القديمة وفهارس للبحث.

## الاختبارات المضافة

`server/tests/ticketInspectionWorkflow.test.ts`

تغطي الاختبارات:

- القيم المميزة لحالات الفحص.
- صلاحية الفني المسند إليه مباشرة ومنع فني آخر.
- نطاق مدير الصيانة العامة ونطاق مدير الإنشاءات.
- صلاحية المشرف مع اشتراط مراجعة المدير.
- الاعتماد التلقائي لنتيجة المدير.
- منع الفني من المراجعة أو اختيار مسار التنفيذ.
- منع اختيار المسار قبل اعتماد الفحص.
- عقد ترحيل قاعدة البيانات وفصل أوامر `ALTER TABLE` لتوافق TiDB.

## التحقق المنفذ في بيئة العمل

- نجح تحليل الصياغة لجميع ملفات TypeScript وTSX المتأثرة باستخدام محلل TypeScript.
- نجح اختبار تشغيلي مباشر على دوال الصلاحيات الفعلية: 15 تحققًا من الإسناد والنطاق والمراجعة والاعتماد واختيار المسار.
- نجحت اختبارات ثابتة للتأكد من وجود حواجز الخادم والحقول والقيم المميزة وإزالة نموذج الفحص القديم المختصر.

## قيد بيئة الاختبار

لم تُشغّل مجموعة Vitest الكاملة لأن مجلد `node_modules` غير موجود في نسخة المشروع داخل بيئة العمل. ملف الاختبار المضاف جاهز للتشغيل داخل بيئة المشروع بعد تثبيت التبعيات عبر أمر الاختبار المعتاد.
